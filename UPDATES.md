# Matrix Play updates

The app checks published releases in the public `relentlesspoetry-coder/Matrix` GitHub repository, including testing/prerelease versions. It selects the highest valid semantic version among the 100 most recent releases, compares it with its compiled version, and rejects downgrades. Checks are cached for 60 seconds. It does not run a background updater or install without a click.

A release contains `update-manifest.json`, a raw detached 64-byte Ed25519 `update-manifest.sig`, DEB and AppImage packages, source ZIP and `SHA256SUMS`. The pinned public key is `update-core/update-public-key.bin`; its SHA-256 fingerprint is `b657a26878bcfa579481379f1cc650d9322b27a0d99bf65f3a30e07de4c3aaff`. Key rotation requires distributing an app with the new public key. Back up the private key securely; never add it to the source repository.

The signed manifest binds schema, repository, version, tag, Linux architecture/package, exact file name, size and SHA-256. URL construction is fixed to this repository, HTTPS redirects are limited to GitHub's release hosts, and metadata/package reads are bounded. Unknown manifest fields, invalid signatures, unexpected packages and size/hash mismatches fail closed. Downloading uses a temporary file and promotes only a verified complete package; cancellation removes the partial file. Valid cached downloads can be reused. Files are checked again immediately before installation.

DEB installations at `/usr/bin/matrix-frontend` use `pkexec /usr/lib/matrix-play/matrix-install-update`; Linux handles authorization, and Matrix Play never reads a password. The DEB packages this compiled helper as a root-owned executable. The app sends the original signed manifest, signature and bounded package bytes through stdin. The helper accepts no command-line arguments, hashes or caller-selected file paths. It independently verifies the pinned signing key, repository, version, architecture and DEB identity, then copies the package into a new root-owned 0700 directory under `/var/cache` (never a caller-supplied TMPDIR). It checks the exact staged file against the authenticated size, hash and package header before invoking absolute `/usr/bin/apt-get` with a cleared environment. That private staging directory remains alive through APT completion and is then removed. Replacing or modifying the user-writable download after verification cannot alter the installed bytes. Existing installations without the helper must install this security update manually; there is no fallback to privileged installation of a mutable user path. AppImage mode requires the running Matrix Play executable to be inside its declared mounted/extracted APPDIR, preventing an inherited APPIMAGE from targeting another program. AppImage installation stages and verifies a new image in the same directory, preserves the existing file as `.previous`, then atomically replaces it. The folder must be writable. A development binary offers to open the verified DEB in the system installer instead. Game folders, settings and covers are not updated by this process.

`python3 scripts/release.py X.Y.Z` requires a clean main checkout and committed release notes. It bumps all application versions, commits and pushes. The Actions build runs tests before the publish job receives the signing secret. Publishing uses only the tested main commit, creates a draft with all assets, then publishes it. Already-published versions are skipped. A failed build or missing signing secret leaves the new version unpublished; fix the issue and rerun or push the correction. Never manually replace signed release assets under an existing version.

The combined DEB/AppImage release and build commands require a numeric `X.Y.Z` version. Tauri CLI 2.12.4 writes the application version directly into the Debian control file and has no DEB-specific version override. Debian sorts `0.6.1-rc.10` above `0.6.1`, so accepting that suffix would break the upgrade to stable. Use GitHub's testing/prerelease status with a numeric version instead. The signer also rejects version suffixes, and the release helper checks both SemVer and actual `dpkg` upgrade ordering before modifying files. Full SemVer comparison remains available for non-DEB consumers such as AppImage update selection; this restriction belongs to the combined DEB release workflow.

Validation must be reported precisely: updater core tests exercise signature/identity checks, corrupt and oversized downloads, cancellation, caching and staged AppImage replacement using synthetic fixtures. UI tests simulate update responses. Real desktop tests check the registered IPC and rendered assets. A separate public-release smoke check can exercise the real HTTPS signature/download path. Those tests do not execute a privileged system package upgrade or certify emulator/game compatibility.


## Secure DEB helper regression checks

Run `cargo test --locked --manifest-path update-core/Cargo.toml` for the privileged protocol tests: forged/oversized metadata, signed downgrade rejection, modified/truncated/oversized package streams, source mutation after staging, and unsafe staging directory rejection. These tests use synthetic packages and a test-only signing key and never invoke APT or pkexec. `cargo build --locked --release --manifest-path src-tauri/Cargo.toml --no-default-features --bin matrix-install-update` builds the helper; Tauri runs this automatically before packaging. Inspect the built DEB to confirm `/usr/lib/matrix-play/matrix-install-update` is root-owned and non-writable by ordinary users. A real authorization/package installation remains a separate, explicitly authorized integration test.
