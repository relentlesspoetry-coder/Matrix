# Matrix Play updates

The app checks published releases in the public `relentlesspoetry-coder/Matrix` GitHub repository, including testing/prerelease versions. It selects the highest valid semantic version among the 100 most recent releases, compares it with its compiled version, and rejects downgrades. Checks are cached for 60 seconds. It does not run a background updater or install without a click.

A release contains `update-manifest.json`, a raw detached 64-byte Ed25519 `update-manifest.sig`, DEB and AppImage packages, source ZIP and `SHA256SUMS`. The pinned public key is `update-core/update-public-key.bin`; its SHA-256 fingerprint is `b657a26878bcfa579481379f1cc650d9322b27a0d99bf65f3a30e07de4c3aaff`. Key rotation requires distributing an app with the new public key. Back up the private key securely; never add it to the source repository.

The signed manifest binds schema, repository, version, tag, Linux architecture/package, exact file name, size and SHA-256. URL construction is fixed to this repository, HTTPS redirects are limited to GitHub's release hosts, and metadata/package reads are bounded. Unknown manifest fields, invalid signatures, unexpected packages and size/hash mismatches fail closed. Downloading uses a temporary file and promotes only a verified complete package; cancellation removes the partial file. Valid cached downloads can be reused. Files are checked again immediately before installation.

DEB installations at `/usr/bin/matrix-frontend` use `pkexec /usr/bin/apt-get install -y <verified absolute package path>`; Linux handles authorization, and Matrix Play never reads a password. AppImage mode requires the running Matrix Play executable to be inside its declared mounted/extracted APPDIR, preventing an inherited APPIMAGE from targeting another program. AppImage installation stages and verifies a new image in the same directory, preserves the existing file as `.previous`, then atomically replaces it. The folder must be writable. A development binary offers to open the verified DEB in the system installer instead. Game folders, settings and covers are not updated by this process.

`python3 scripts/release.py X.Y.Z` requires a clean main checkout and committed release notes. It bumps all application versions, commits and pushes. The Actions build runs tests before the publish job receives the signing secret. Publishing uses only the tested main commit, creates a draft with all assets, then publishes it. Already-published versions are skipped. A failed build or missing signing secret leaves the new version unpublished; fix the issue and rerun or push the correction. Never manually replace signed release assets under an existing version.

Validation must be reported precisely: updater core tests exercise signature/identity checks, corrupt and oversized downloads, cancellation, caching and staged AppImage replacement using synthetic fixtures. UI tests simulate update responses. Real desktop tests check the registered IPC and rendered assets. A separate public-release smoke check can exercise the real HTTPS signature/download path. Those tests do not execute a privileged system package upgrade or certify emulator/game compatibility.
